## Working status notes

- Owner decision (2026-08-20): full port of everything shadcn ships - nothing refused. Third-party runtime deps installed and pinned exact (react-day-picker 10.0.1, date-fns 4.4.0, embla-carousel-react 8.6.0, recharts 3.10.1, cmdk 1.1.1, @tanstack/react-table 9.1.2, react-resizable-panels 4.12.3, @shadcn/react 0.3.0 - subpath-only exports); all react-19-compatible at latest stable. The design-notes "no extra runtime deps" policy is to be updated accordingly.
- Owner decision (2026-08-20, reversing the earlier "keep icons inlined" call): the kit IMPORTS icons from `lucide-react` (pinned exact 1.33.0, a regular `dependency` like the other runtime deps), rather than carrying copied SVG-path components. Direct `import { ChevronDownIcon } from 'lucide-react'` at each use site, exactly as upstream shadcn does - no local wrapper components, no re-export shim, no icon registry, no dynamic imports. `rollup-plugin-node-externals` externalizes it, so `dist/*.js` carry bare `lucide-react` imports and bundle none of it. Migration is complete across every component and demo example - `grep` finds no copied lucide path data anywhere in `src/`, `demo/` or `dist/`. NOTICE therefore needs no lucide entry: nothing is copied in any more, and an installed dependency ships its own ISC LICENSE. The inline `<svg>`s still in `*.test.tsx` fixtures and in `*.md` examples are deliberately raw - they stand in for a CONSUMER's own icon, which is exactly what the `.item svg` / `.alert > svg` sizing rules exist to catch.
- Conformance audit done (2026-08-20) against the shadcn base registry sources (`apps/v4/registry/bases/base/ui/`): 7 MATCH, 10 MINOR DRIFT, 2 DIVERGENT. The two divergent components (`badge`, `field`) were renamed to `-backup` and re-ported fresh under the canonical names (done, see rows); minor-drift components get parity upgrades in place (add the missing upstream surface, keep our additive props) - still pending.
